# 六维文本与隐藏状态难度信号分析

## 结论

当前数据能区分两种不同的“难”：

- `code_L5_005` 是**任务复杂度高**：六维文本明显变长、验证项和工具动作增多，生成末段隐藏状态也比同类题更不稳定。但这些信号只能说明任务复杂，不能保证模型能正确实现；最终代码仍在时钟回拨和动态调速处出错。
- `logic_L3_018` 是**模型求解不收敛**：六维文本阶段没有明显预警，反而是五道逻辑题中最短的计划；直到无提示直接作答时，才出现 4096-token 截断、严重重复和末段隐藏状态不收敛。这说明当前六维输出存在明显假阴性。

因此，不能用一个隐藏状态漂移指标直接代表问题难度。较可靠的方案是把“六维文本的任务复杂度信号”和“实际生成过程的非收敛信号”分开，再与可执行验证结合。

## 六维输出阶段

### `code_L5_005`

与其余四道代码题的均值相比：

| 指标 | Code L5 | Code L1–L4 均值 | 观察 |
|---|---:|---:|---|
| 生成 token | 808 | 407.8 | 约为同类题两倍 |
| 验证相关词频 | 10 | 2.75 | 明确意识到测试和边界风险 |
| 4-gram 唯一率 | 0.773 | 0.934 | 清单内容有较多重复 |
| 末 32 token / 前 32 token 步间漂移比 | 0.795 | 0.485 | 末段没有像同类题一样明显稳定下来 |
| 后 8 个深度转换平均余弦距离 | 0.11222 | 0.11065 | 同类题最高，但绝对差异较小 |

文本本身正确列出了并发、时钟回拨、动态速率、阻塞模式和测试等难点，因此很适合做“复杂度预警”。但它没有给出单调时钟或负时间差钳制、调速前按旧速率补充 token、避免持锁睡眠等具体不变量。也就是说，它识别出了风险区域，却没有证明模型已经具备正确解决这些风险的方案。

### `logic_L3_018`

| 指标 | Logic L3 | 其余逻辑题均值 | 观察 |
|---|---:|---:|---|
| 生成 token | 367 | 466.5 | 五道逻辑题中最短 |
| 不确定/冲突相关词频 | 5 | 3.75 | 有一定风险意识 |
| 4-gram 唯一率 | 0.931 | 0.906 | 没有重复或挣扎迹象 |
| 末 32 / 前 32 步间漂移比 | 0.747 | 0.626 | 略高，但并非唯一异常 |
| 后 8 个深度转换平均余弦距离 | 0.10883 | 0.10844 | 接近同类均值 |

六维文本只说要“系统分析”“逐步排除”“避免矛盾”，没有真正列出两种可能的白—绿位置，更没有发现两种都会使红色紧邻蓝色。它把工具维度判为无需工具。这份输出无法在作答前可靠识别该题无解。

## 原题 prompt 状态

从六维分支的完整隐藏状态中只截取原题 token，在模型开始生成六维文本之前计算后 8 个深度转换：

- Code L5：0.11117，低于 Code L1–L4 均值约 0.12147。
- Logic L3：0.12346，高于其余逻辑题均值约 0.11680。

两个困难样本向相反方向偏离，因此“层间变化越大，题越难”或“越小，题越难”都不成立。该指标更可能同时受到题目长度、词汇、句法和任务类型影响。

## 直接作答阶段

`logic_L3_018` 出现了非常强的在线非收敛信号：

| 指标 | Logic L3 | 其余逻辑题均值 |
|---|---:|---:|
| 生成 token | 4096，触发上限 | 639.8 |
| 4-gram 唯一率 | 0.177 | 0.829 |
| zlib 压缩比 | 0.087 | 0.402 |
| 末 32 / 前 32 步间漂移比 | 1.508 | 1.171 |
| 后 8 层末段深度转换 | 0.11458 | 0.10974 |

模型实际上很早就枚举出仅有的两类布局并发现它们均违反条件，但没有把“所有情况均失败”提升为“题目无解”，而是重复相同枚举直到截断。低 4-gram 唯一率和极低压缩比直接刻画了这种循环。

`code_L5_005` 的基线回答为 1552 token，在代码题中最长，最后正常 EOS 结束；它没有像 Logic L3 那样循环。它的问题属于局部语义和工程不变量错误，而不是生成不收敛，因此仅看长度或隐藏状态漂移很难发现，必须运行针对性的测试。

## 全部 25 题的总体关系

六维分支中，指标与题库 L1–L5 等级的 Spearman 相关为：

| 指标 | Spearman ρ | p 值 |
|---|---:|---:|
| 生成 token 数 | 0.549 | 0.004 |
| 不确定性词频 | 0.484 | 0.014 |
| “不适用/未体现”词频 | -0.504 | 0.010 |
| 平均步间隐藏状态距离 | -0.141 | 0.501 |
| 末段步间距离 | 0.067 | 0.751 |
| 末段/前段漂移比 | 0.071 | 0.737 |
| 后 8 层深度转换 | 0.012 | 0.955 |

在这 25 个样本中，文本长度和不确定性表述与人工难度等级有中等相关，而简单隐藏状态漂移几乎没有相关性。样本量很小，且每个等级混合了五种任务类型，这些数字只能作为探索性证据。

## 建议的难度感知方法

建议把“难度”拆成三个独立目标：

1. **任务复杂度**：在六维输出中提取同题型标准化后的长度、相互作用约束数量、具体失败模式、验证步骤和真实工具需求。Code L5 会在这一层被标为高风险。
2. **生成非收敛**：在线监控 token 使用比例、重复 n-gram、压缩比、末段/前段隐藏漂移比和是否迟迟不产生结论。Logic L3 会在这一层被强烈标记。
3. **答案错误风险**：使用题型对应的外部验证器，例如代码测试、约束求解器、精确字数检查或事实来源核对。Code L5 的时钟错误只能在这一层可靠发现。

不要单独使用隐藏状态阈值。可先按题型做 z-score，再用至少两个不同来源的信号共同触发风险，例如“输出长度异常或约束密度高”加上“重复率高或末段漂移不降”。最后应通过多次随机种子、题目改写和更大样本做留出验证，避免在 25 道题上过拟合。
